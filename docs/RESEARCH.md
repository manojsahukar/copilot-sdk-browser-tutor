# GitHub Copilot SDK — findings (checked 2026-10-19, SDK @github/copilot-sdk 1.0.22, repo HEAD b96cd2b, 2026-10-16)

| Question | Answer | Source |
|---|---|---|
| Languages | Node/TS, Python, Go, .NET, Java, Rust (MIT) | https://github.com/github/copilot-sdk#available-sdks |
| Needs Copilot CLI/runtime? | Yes: SDK talks JSON-RPC to the Copilot runtime. For Node/Python/.NET it is bundled (npm optional dep `@github/copilot-sdk-<platform>`, linux-x64 = 154 MB; spawns `copilot-runtime --headless --stdio`; glibc ≥ 2.28; musl + arm64 builds exist). Can also connect to an external runtime via `RuntimeConnection.forUri`. | README "Architecture"/FAQ; docs/setup/bundled-cli.md; verified in node_modules |
| Per-user auth | Yes. Create OAuth App **or** GitHub App, run normal web flow, pass the user's token as `gitHubToken` (client- or **per-session**); "Copilot requests are made on behalf of each authenticated user, using their Copilot subscription". Token types: `gho_` (OAuth app) ✅, `ghu_` (GitHub App user token) ✅, `github_pat_` ✅, `ghp_` classic PAT ❌. Rotating tokens via `gitHubTokenProvider`. | https://github.com/github/copilot-sdk/blob/main/docs/setup/github-oauth.md ; docs/auth/authenticate.md ; https://docs.github.com/en/copilot/how-tos/copilot-sdk/setup/github-oauth |
| Required OAuth scopes | **Not documented.** Verified working: a `gho_` token from gh CLI's OAuth app (scopes gist, read:org, read:user, repo). Whether a custom OAuth app token with only `read:user` works is **unverified** until the app exists. | — |
| Multi-user server guidance | Use `mode: "empty"` (no ambient OS/file tools), per-session `gitHubToken`, explicit `availableTools` allow-list (`custom:*`), unique session IDs, idle timeouts. Default `copilot-cli` mode must not be used for shared servers. | https://github.com/github/copilot-sdk/blob/main/docs/setup/multi-tenancy.md |
| BYOK | Yes: per-session `provider` config (OpenAI, Azure/Foundry, Anthropic, OpenAI-compatible); no GitHub auth or Copilot plan needed; key-based only (no Entra/managed identity). | docs/auth/byok.md ; README FAQ |
| Tools | `tools: [{name, description, parameters (JSON Schema or Zod via defineTool), handler, skipPermission?}]`; `onPermissionRequest` approves/rejects each call. | nodejs/README.md "Tools", "Permission Handling" |
| Streaming | `streaming: true` → `assistant.message_delta` events; also `tool.execution_start`, `session.idle`, `session.error`. | nodejs/README.md "Streaming" |
| Billing | Each prompt counts against the user's Copilot allowance, same as Copilot CLI. Copilot plan required unless BYOK (README mentions the free tier). | README FAQ |
| Licensing/terms | SDK code is MIT. Docs explicitly position the OAuth setup for "multi-user apps, internal tools, SaaS products". Usage is governed by GitHub ToS + Copilot product terms of each user's plan; I found **no explicit clause** for/against third-party multi-user web apps beyond that — have the Copilot Product Specific Terms reviewed before any public launch. Org-owned Copilot seats may be blocked if the org restricts third-party OAuth apps. | https://docs.github.com/site-policy/github-terms/github-terms-of-service |
