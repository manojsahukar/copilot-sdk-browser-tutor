A chat widget that runs entirely in your browser

Pilot of the client-side OpenRouter widget — no backend, built to drop into any static GitHub Pages site.

This documentation site is a live demo of a framework-free chat widget you can add to a static website with a single script tag. There is no server behind the chat: everything — signing in to OpenRouter, holding the key, calling the model, rendering the answer — happens in your browser.

How it works

Tap Ask in the corner, then Connect OpenRouter. The widget runs an OAuth PKCE flow and brings back a scoped sk-or key. Your messages go straight to https://openrouter.ai/api/v1/chat/completions with streaming. The default model is openrouter/free (“Auto (free models only)”), so a default chat costs nothing; you can switch to openrouter/auto (“Auto (best available)”, may bill paid models) from the picker.

It reads this page, and the whole site

The widget sends the visible text of the page you are on as context, so it can answer questions about what you are reading. It also loads a small site-index.json built at deploy time and does lightweight in-browser retrieval (BM25) across every page, so it can answer site-wide questions and cite the page it used.

Try asking: "Where is my OpenRouter key stored?", "Why is a client-side key an XSS risk?", or "Who pays for the model calls?" — the answer should link to the matching page.

    How the tool call works

    1. This page defines three tools in JavaScript: set_color, get_color and reset_color. Each tool has a name, a short description and a JSON schema for its input.
    2. When you send a message, the widget sends the tool list to OpenRouter together with your question.
    3. If the model wants to change the color, it replies with a tool call. A tool call is a tool name and its arguments in JSON.
    4. The widget runs the tool in your browser, and the color changes. The chat shows the tool name, the arguments and the result.
    5. The widget sends the result back to OpenRouter. Then the model writes its final answer.

    The widget stops after four rounds of tool calls. Tool calls work only with the OpenRouter provider. With the other providers, the chat answers with text only. Some free models cannot use tools. If you get an error, send the message again or pick another model.

    The same tools for an outside assistant (WebMCP)

    WebMCP is a proposed web standard. It lets a page offer its tools to an AI assistant in the browser, for example a browser agent or an extension.

    This page registers the same three tools with document.modelContext.registerTool(). The widget and WebMCP use the same tool code and the same input rules.

    Your browser does not support WebMCP, so only the chat widget can use these tools. The rest of the page works as usual. To try WebMCP, use Chrome 146 or later. Open chrome://flags/#enable-webmcp-testing, set it to Enabled, and relaunch Chrome. Then open this page with an agent that supports WebMCP, for example the Model Context Tool Inspector extension from Chrome.

    The safety rule

    The tools can change only the color on this page. They cannot read your key, send data or run code.

    The color must be a hex value or a name from a fixed list. If the input is not valid, the tool returns an error and changes nothing.

    The page never runs code that the model writes. The model can only choose a tool from the list and give its arguments.

    The chat shows each tool call as plain text, not as HTML. A tool result cannot add a script to the page.

    Security model

    The pilot pages are locked down with a meta-tag CSP: script-src 'self' and connect-src 'self' https://openrouter.ai, with no inline scripts, no inline styles and no eval. Model output is rendered through the vendored marked + DOMPurify pipeline, so a hostile reply cannot inject script. See the linked pages for where the key lives, the XSS trade-off, and who pays.

    This widget is deliberately separate from the Browser Tutor's own server-side OpenRouter session. It uses its own btw_* sessionStorage keys and never touches the tutor's login cookie or saved chat.
