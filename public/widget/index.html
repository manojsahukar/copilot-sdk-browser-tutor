A chat widget that runs entirely in your browser

Pilot of the client-side OpenRouter widget — no backend, built to drop into any static GitHub Pages site.

This documentation site is a live demo of a framework-free chat widget you can add to a static website with a single script tag. There is no server behind the chat: everything — signing in to OpenRouter, holding the key, calling the model, rendering the answer — happens in your browser.

How it works

Tap Ask in the corner, then Connect OpenRouter. The widget runs an OAuth PKCE flow and brings back a scoped sk-or key. Your messages go straight to https://openrouter.ai/api/v1/chat/completions with streaming. The default model is openrouter/free (“Auto (free models only)”), so a default chat costs nothing; you can switch to openrouter/auto (“Auto (best available)”, may bill paid models) from the picker.

It reads this page, and the whole site

The widget sends the visible text of the page you are on as context, so it can answer questions about what you are reading. It also loads a small site-index.json built at deploy time and does lightweight in-browser retrieval (BM25) across every page, so it can answer site-wide questions and cite the page it used.

Try asking: "Where is my OpenRouter key stored?", "Why is a client-side key an XSS risk?", or "Who pays for the model calls?" — the answer should link to the matching page.

Security model

The pilot pages are locked down with a meta-tag CSP: script-src 'self' and connect-src 'self' https://openrouter.ai, with no inline scripts, no inline styles and no eval. Model output is rendered through the vendored marked + DOMPurify pipeline, so a hostile reply cannot inject script. See the linked pages for where the key lives, the XSS trade-off, and who pays.

This widget is deliberately separate from the Browser Tutor's own server-side OpenRouter session. It uses its own btw_* sessionStorage keys and never touches the tutor's login cookie or saved chat.
