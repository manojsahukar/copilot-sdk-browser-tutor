Where your OpenRouter key lives

When you connect OpenRouter in this widget, the issued sk-or key is stored in sessionStorage under the key name btw_or_key. sessionStorage is scoped to this one browser tab and this one origin, and it is cleared automatically when you close the tab.

Why sessionStorage and not a cookie

A cookie would be sent to the server on every request — but there is no server here, and we never want the key to leave your browser except in the Authorization header to OpenRouter itself. sessionStorage keeps the key client-side, per-tab, and short-lived. The Disconnect button wipes btw_or_key, the cached user id, the model choice and the chat history immediately.

The sign-in round-trip

When you tap Connect OpenRouter, the widget creates a one-time PKCE code_verifier and a random state and keeps them in localStorage under btw_pkce for at most 10 minutes (OpenRouter's code lifetime). It is localStorage rather than sessionStorage because on phones the return from OpenRouter can open in a new tab, a Custom Tab or an installed-app window, where this tab's sessionStorage does not exist. The entry is deleted the moment the return is handled, the state must match, and the code is scrubbed from the address bar. The verifier alone is useless without the code.

Optional: remember on this device

By default the key is session-only. If you tick Remember on this device for 7 days, a copy goes to localStorage (btw_or_key_persist) with a 7-day expiry, so it survives closing the tab and is picked up by your other tabs. That is more convenient but riskier: until it expires, any script running on this site could read it. Only use it on your own device; Disconnect wipes it.

What is NOT used

Apart from the short-lived sign-in entry above and the opt-in remember copy, the key never goes to localStorage, and the widget never touches the tutor's own login cookie bt_sess or its saved transcript bt_chat. It only uses its own btw_-prefixed keys. Conversation history also lives only in sessionStorage and disappears when the tab closes.

Rule of thumb: a key in sessionStorage is readable by any JavaScript running on this origin. That is the visitor's own risk, which the XSS page explains.
